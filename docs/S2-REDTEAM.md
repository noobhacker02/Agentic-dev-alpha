# S2 red-team matrix: what was attacked, by which test, and what the far side counted

The exit criterion for S2 (LIVE mode) in [HYBRID-AGENT-SPEC.md](HYBRID-AGENT-SPEC.md) is "red-team rows for off-site navigation, redirects, private addresses, DNS rebinding, profile theft (including through a
symlink), two agents on one profile (including after a reboot and Chromium's own lock), consent banners, upload destination". This file maps each row to the test that attacks it and says what that test counts on
the other side, so a reader can check a claim by running one command. Everything runs against a local "internet" (one server answering for several host names, a resolver stand-in, an "is this address public"
stand-in); nothing here touches a real site. Rows marked **not covered** are said plainly; they are not claimed.

Run any one with `npm run build && npm run test:<name>`. The benchmark row `live-gate` (156 rows, [BENCHMARK.md](BENCHMARK.md)) scores the classification of URL, address, request, socket, landing and file-destination forms
on every run.

| Row | Attack | Test (section) | What is counted, and the control |
|---|---|---|---|
| Off-site navigation | `open` to an unlisted, denied or look-alike name (`linkedin.com.evil.com`, `evil.com/linkedin.com`, `@`, `#@`, homographs, punycode), every address spelling (decimal, hex, octal, shorthand, IPv6, mapped), another port, other schemes, credentials | `live-browser` (0, 2), `allowances` (1, 2, 3, 5), bench `live-gate` (open rows) | the far side receives 0 requests; control: the listed name, its subdomains, upper case and a trailing dot open |
| Off-site navigation, from the page | a link, a script navigation, a meta refresh, an iframe, a popup, a WebSocket to an unlisted host | `live-browser` (3, 7) | aborted before any request; the agent is told which host and why; control: a link and an iframe to another **listed** host work |
| Redirects | a 302, a chain of three, a page that stalls while loading, a redirect inside an iframe, a redirect between listed hosts | `live-browser` (5, 6) | the request to the off-list host **is made** (asserted: it cannot be recalled); the page is blanked and none of its text or title reaches the agent; control: a redirect between listed hosts shows the page |
| Private addresses | a listed name that resolves to a private address, cloud metadata, a LAN address, an IPv4-mapped or NAT64 loopback, every literal and `localhost` | `live-policy` (3, 5), `live-browser` (8), `allowances` (6), bench `live-gate` (public rows) | the decoy on the private address receives 0 connections; control: a public address passes |
| DNS rebinding | a name that answers "public" the first time and "private" the second | `live-policy` (4) | one lookup per connection and the connection goes to the address that was checked: the decoy receives 0 |
| Profile theft, through a symlink | a link in place of `profiles/` or `<site>/`, a file in place of either, a home reached through a link, a directory owned by someone else, a profile inside or around the working directory or `--dir` (including a directory named `..x`, and one that does not exist yet under a link) | `profile` (2, 3, 4, 5), `login` (5) | nothing is made behind a link; a refused profile leaves no directory in the place it was refused for |
| Profile theft, through the file tools | `Read`, `Write`, `Edit`, `Glob`, `Grep` of `<home>/profiles/...` directly, through a link inside `--dir`, with `link/..`, with `~`; and a shell command that names a credential file inside `--dir` | `path-scope-symlink`, `path-text`, `bash-sensitive` | denied or asked; control: ordinary files in `--dir`, and `.env.example`, stay allowed. **Not covered:** a recursive `grep -r x .` that reaches a credential file without naming it (threat D5) |
| Two agents on one profile | a second session and a login while the first holds the profile; six real processes racing; a dead holder; a pid reused after a reboot (alive, but its start time differs); a lock mid-write; two recoverers of one stale lock interleaved on purpose; a recovery mutex left by a dead process | `profile` (6, 7, 10, 12, 13), `login` (3) | exactly one holder at a time, the others are told its pid; a live or unprovable holder is never displaced |
| Chromium's own lock | `SingletonLock`/`Cookie`/`Socket` left by a dead Chromium; one naming another computer; one naming a live process | `profile` (8), `login` (7c) | removed only when the owner is gone; refused otherwise, and the profile lock is released |
| A real reboot | a machine restarted between two runs | **not covered:** the case is simulated (a lock naming a live pid whose real start time differs; real start times carry the Linux boot id) | |
| Consent banners | a cookie dialog over a fresh profile | **not covered in S2:** nothing in S2 clicks. A banner served from a third-party frame does not load (a frame is judged by the list); the click that dismisses it is the job flow's, with the minimum option (threat E10, S5) | |
| Upload destination | a form that posts to an unlisted host, another listed platform or a `javascript:` address; a button's own `formaction`; an image button; a field outside any form; a frame of another platform (also one nested in it); an input named `action`/`elements`; a hostile `<base>`; accessors the page overrode; a form with no `method`; an action that is not an address; a form that answers in another window | `upload-form` (0 to 3) | 0 uploads, the field stays empty and the page's `change` event never fires; control: the same shape posting to the page's own site, a subdomain, a shadow root or a frame of its own site is attached |
| Upload, after the check | the page rewrites its form after the look, or at the moment of attaching; a script sends the file with `fetch`; the page opens a window whose form posts elsewhere; a script only changes the address; an XHR with method `OPTIONS` and a body; a shared worker; a WebSocket to another listed platform; a page that stored the bytes and reloaded | `upload-form` (1, 4, 4a, 4b, 5) | 0 reach the other site; the agent is told ("blocked by the upload rule"); the form's own site (a request or a socket) still receives the file; a reload of the same site's page keeps the hold, and going to another site ends it |
| Upload, the file | a path instead of a name (`/etc/passwd`, `../..`, `~/.ssh/id_rsa`), a link, a swapped parent directory, a changed content pin, a script or key type, a file inside the agent-loop directory | `uploads` (1 to 4), `upload-form` (6) | refused without echoing the path or the user's directory |

| Popups, tabs | a popup carried off the list by a redirect (committed before the browser reports it) | `live-browser` (5b) | the tab listing shows neither its title nor its address, a notice says where it landed, and the page is blanked; control: a popup to a listed host is listed with its title |
| Deny list, odd names | `x_y.ads.example.org`, a name with a space, a trailing dot | `allowances` (8) | `denied`, not `unlisted`; the net gate refuses it; control: an odd name under no denied domain stays `unlisted` |
| Two agents, two namespaces | a lock written by a process in another PID namespace (container, sandbox) | `profile` (16) | held, never recovered; control: the same namespace, and a lock with no namespace recorded, are judged by pid and start time |

Residual risks that no test here removes, stated in the threats document: a script on a listed site can reach any public host with a GET (D1); the profile's cookie is readable by the same operating-system user
and a Bash `cat` of it outside `--dir` is the user's to approve (D5); the credential-path list is a list of names (widened in round 3), so a secret kept under an unlisted name is not recognised; the page-side half of the upload check runs in the page's own world and is advisory, the network rule is what holds (B12) -- except for a WebSocket opened inside a dedicated worker, which the browser does not route (round 3 A56, scheduled for S5), and bytes a page passes to another document of the same site by means the origin does not isolate (`window.name`, a cookie on a parent domain). Plain `http:` to a listed name is still opened (A61, S5).
